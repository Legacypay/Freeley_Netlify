# public/

## Purpose
Astro's static-asset passthrough directory: everything here is copied verbatim into `dist/` at build time (`npm run build` → `astro build`), with no processing. In most Astro projects that means fonts/favicons/robots.txt. In this repo it also means **130 standalone legacy `.html` pages** — the entire pre-Astro-migration site (blog articles + funnel/utility pages) — plus their own CSS/JS/images, copied here wholesale during the 2026-07-17 Astro migration so their exact original URLs kept working. Astro's live pages (`src/pages/*.astro`) are a separate, newer system that happens to share this deploy and, in a few cases (`global.css`, `style/*.css`, `assets/js/*.js`, `quiz-scripts/asw.js`), share these same static files.

**Live-vs-legacy status (read before touching anything here):** the build genuinely emits all 130 root `.html` files into `dist/`, and `netlify.toml` has a permanent rule 301-redirecting `/*.html` → the clean URL, confirming they're meant to be real routes. But `netlify.toml` currently also carries a temporary **"COMING SOON GATE"** block (clearly marked, with its own removal instructions) that force-rewrites every URL to `/waitlist` (`from = "/*", to = "/waitlist", status = 200, force = true`) except an explicit allowlist evaluated first. None of the 130 root legacy `.html` slugs are on that allowlist. **Net effect: right now, in production, none of these legacy pages are reachable — every one of their URLs currently serves the waitlist page instead.** They are not dead code; they are gated-but-live content that resumes serving automatically the instant that gate block is deleted. Do not delete them or treat them as orphaned cruft; do not "clean them up" without checking `netlify.toml`'s gate status first.

## For AI Agents
### Working In This Directory
- Before editing or deleting anything at the `public/` root, check whether it's referenced from `src/` (Astro, live) or only from the root `.html` files (legacy). `grep -rl "<filename>" ../src public/*.html` is the fast way to tell.
- Before assuming a root `.html` page is dead, check the "COMING SOON GATE" block in `../netlify.toml` — if it's still present, every legacy page (and most real routes) is currently gated behind `/waitlist` regardless of what's built.
- Do not add new files at the `public/` root without checking `netlify.toml`'s gate allowlist — an ungated absolute-path asset (like `/global.css`, `/analytics.js`) needs an explicit pass-through rule there or it will silently 200 with the waitlist HTML instead of the real file (wrong MIME type, breaks the browser's script/style loading).

### Testing Requirements
No automated tests. Verify a legacy page by opening `dist/<slug>.html` after `npm run build`, or `netlify dev` locally (which does not apply the production gate the same way `netlify.toml`'s redirects do on the live site — check behavior against a real deploy preview if the gate matters).

### Common Patterns
- Legacy `.html` pages: full standalone `<!DOCTYPE html>` documents, Google Fonts (`Cormorant Garamond` + `DM Sans`/`Montserrat`) via `<link>`, `shared.css` + inline `<style>`, `shared.js`, root-relative asset paths (no leading `/`).
- Astro pages needing an asset in `public/`: reference it with a **leading slash** absolute path (`/global.css`, `/assets/js/wl-script.js`) — and if it's a new top-level file, add a pass-through rule to the gate's allowlist in `netlify.toml`.

## Dependencies
### Internal
- `../src/pages/*.astro` (several depend on `global.css`, `style/*.css`, `assets/js/*.js`, `products-imgs/`, `quiz-scripts/asw.js`)
- `../astro.config.mjs` (injects `analytics.js`/`attribution.js` script tags and the Whop pixel into every Astro page head)
- `../netlify.toml` (owns the waitlist gate, the `.html`→clean-URL redirect, and the allowlist that decides what in this directory is actually reachable)
- `../content/blog/*.md` + `../build_blog.js` (source of the legacy SEO articles, currently disconnected from the live build)

### External
- Google Fonts (Cormorant Garamond, DM Sans, Montserrat) — legacy pages link these directly; Astro pages self-host via `astro.config.mjs`'s `fonts` config instead.
- Tidio (legacy `.html` pages only, via `shared.js`). Tawk.to (previously used on Astro pages) was removed site-wide 2026-08-14 — no live-chat widget currently on the Astro pages.
